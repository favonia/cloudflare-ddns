# Documentation

This directory holds the public documentation set beyond the top-level `README.markdown`.

## Top-Level Documents

- `docs/CONTRIBUTING.markdown`: contributor workflow and expectations.
- `docs/CODE_OF_CONDUCT.markdown`: community conduct rules.
- `docs/SECURITY.md`: supported versions and vulnerability reporting.
- `docs/release-workflow.markdown`: maintainer release and feature-note conventions.
- `docs/design/`: durable design documents for future developers, including AI agents.
- `docs/rationale/`: non-normative design arguments, alternatives, evidence limits, and revisit conditions; start with [the rationale index](rationale/README.markdown).

For `docs/design/`, start with [`docs/design/README.markdown`](design/README.markdown).

## Punctuation

Use these conventions in project-authored prose across the README, changelog, design notes, and other documentation, including release notes and security advisories:

- Use typographic apostrophes and quotation marks: `’`, `“…”`, and `‘…’` for a quotation within a quotation.
- Use an en dash for numeric ranges (8–32), an em dash without surrounding spaces for a sentence break, and the ellipsis character (`…`) in prose. Keep ordinary hyphens in compound words.
- Preserve exact characters in code, commands, configuration values, paths, URLs, Markdown and HTML syntax, and verbatim source material such as historical commit titles and third-party documents. Put literal values and output in code spans or code blocks so they remain safe to copy.
